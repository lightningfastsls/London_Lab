   reports), and proposed wiki-links to existing notes.
2. Invoke `/reduce` on the inbox item to extract atomic claims.
3. Invoke `/reflect` after to wire up connections to:
   - `[[notch-injection migration measures cleaning quality better than passive cohort sampling]]`
   - `[[falsifiable cleaning gates with numeric thresholds beat vibes-based judgment]]`
   - Any existing methodology note about VAE training.
4. Run `/verify` on the new note to check schema compliance.

**Reference content to seed the inbox file:**

> **Claim**: Diagnostic VAE epoch budgets must scale with input feature
> count. Smoke-test defaults calibrated on 32×32 synthetic data
> (1,024 features) silently produce degenerate K-NN diagnostics when
> applied to real spectrograms (227×227 = 51,529 features, ~50× the
> smoke regime).
>
> **Evidence**: Module 18.2a cleaning-validation gate. First real-data
> run at `--n-epochs 4` (the smoke-test default) produced
> `notch_injection_migration = 1.0` on `all_layers` → false NO-GO.
> Re-run at `--n-epochs 32` produced 0.0 → correct GO. No other
> change between runs. Raw-pixel diagnostics
> (`per_band_cohens_d`, `raw_pixel_pca_d`), which do not use the
> VAE, were identical between runs — isolating the cause.
>
> **Mechanism**: With cohorts compressed to near-overlap by the full
> cleaning stack (per_band_d=0.07, PCA_d=0), the residual cohort
> signal is small. An under-trained VAE maps that small signal into
> a noisy latent geometry. A coherent +2σ injection then pushes ALL
> cohort_B encodings to one side of whatever weak decision boundary
> the VAE happens to find — giving migration = 1.0.
>
> **Generalization**: Applies to any diagnostic that uses learned
> representations to measure cohort properties. Rule of thumb:
> training compute should scale with feature dimensionality. Bonus
> safety net: add a convergence check (loss-plateau detection) that
> re-trains when reconstruction is still falling.
>
> **Source**: `docs/handoffs/cleaning-validation-report.md` Interpretation
> section. Module 18.2a IMPLEMENTATION_PROGRESS entry. Commits
> `9e4540d9`, `0a47015e`, `a515e2f6` on
> `worktree-lab-cnn-classifier-plan`.

**Verification.** `notes/` should have 1-2 new atomic claim notes after
`/reduce`, each with at least 2 incoming wiki-links after `/reflect`.

## Relevant Constraints (vault flattened, for offline reference)

These constraints are pulled from the worktree's vault canary
references; flatten here so the next session doesn't need to re-search.

1. **Production CNN is `models/hard_neg_retrain/best_model.pt`** —
   not the older `matched_windows` or `production` models. The
   classifier pipeline uses this for any inference-mode validation
   in 18.2b downstream tests.
2. **`corpus.SAMPLE_RATE_HZ = 300_000`** (ADR-001) is fixed by the
   hardware and the CNN's training grid. Never modify or redeclare.
3. **STFT params are corpus.STFT_N_FFT=512, corpus.STFT_HOP=128**
   (ADR-002). Import; never redeclare.
4. **Classifier pipeline operates at 250 kHz** via
   `classifier.TARGET_SAMPLE_RATE_HZ = 250_000` (VocalMat-aligned, C1).
   Resampling factors: up=5, down=6 (rational 300→250).
5. **VocalMat naming uses snake_case** (`mult_steps`, not
   `multi_steps`). 12 classes total. mult_steps has 74 files total
   on OSF — smallest class by 1.8× margin.
6. **VocalMat PNGs are 227×227 RGB** (AlexNet input convention) with
   a perceptual colormap. The 18.2a loader converts to luminance for
   the gate; 18.2b will need the same convention for training patches
   per ROADMAP D1.
7. **`notch_depth_db` parameter is deprecated** — emits
   `DeprecationWarning` when given non-default values. Existing
   callers all use `notch_depth_db=20.0` and continue silently.
8. **Diagnostic VAE epoch budget scales with input feature count.**
   Smoke (32×32): 4-8 epochs. Real (227×227): ≥32 epochs. Documented
   in `train_diagnostic_vae` docstring + `--n-epochs` CLI help.
