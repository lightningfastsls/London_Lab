# Investigation 4.1: Task-Aware Context Surfacing

> **Status:** COMPLETE
> **Date:** 2026-03-22
> **Context:** Priority 4.1 from arscontexta health restoration plan
> **Critical file:** `.claude/hooks/session-orient.ps1` (knowledge activation section, lines 222-339)

## Problem Statement

`ops/session-relevance.md` shows "No strong matches above relevance threshold" for BOTH active goal threads. The session-orient hook is supposed to surface vault notes relevant to active goals at session start, but it returns nothing.

## Root Cause Analysis

### Primary: qmd shim is broken on Windows (CRITICAL)

The npm-installed `qmd` command has a broken PowerShell shim at `C:\Users\light\AppData\Roaming\npm\qmd.ps1`. The shim tries to invoke `/bin/sh.exe` which doesn't exist on Windows:

```powershell
# From qmd.ps1 line 24:
& "/bin/sh$exe"  "$basedir/node_modules/@tobilu/qmd/bin/qmd" $args
# Resolves to: & "/bin/sh.exe" ...
# FAILS: /bin/sh.exe doesn't exist on Windows
```

When session-orient.ps1 calls `& qmd search ... 2>&1` and `& qmd vsearch ...`, both fail with `CommandNotFoundException`. The `catch {}` blocks silently swallow these errors, resulting in empty `$threadNotes` and "No strong matches" for every thread.

**This means knowledge activation has NEVER worked on this Windows system.** The "No strong matches" output is not a retrieval quality issue — it's a complete execution failure.

### Secondary: BM25 dilution in query construction (would affect results even if qmd worked)

Even if qmd were callable, the query construction has issues:

1. **Vsearch query dilution** (lines 257-261): Concatenates thread title + first sentence of description, truncated to 120 chars. For "DeepSqueak Classification Bridge", the vsearch query becomes:
   ```
   "DeepSqueak Classification Bridge Phase 2 (Raven export) DONE, Phase 3 (MATLAB import+clustering) IN PROGRESS."
   ```
   This is ~110 chars of mostly status noise. Our 4.3 benchmark proved this returns 0 results.

2. **Title word stripping** (line 264): `$threadTitle -replace '[^\w\s]', ''` removes periods from version numbers, turning "Phase 5.3" into "Phase 53". Combined with BM25, this produces garbage queries.

3. **Keyword query dilution for "Phase 5.3"**: After stripping, the keyword search for "Phase 53" returns 0 results (no notes contain "Phase 53").

## Proposed Fix

### Fix 1: Use node directly instead of broken shim (REQUIRED)

Replace `& qmd` calls with direct node invocation:

```powershell
# At top of knowledge activation section, resolve qmd path:
$qmdScript = Join-Path $env:APPDATA "npm\node_modules\@tobilu\qmd\dist\cli\qmd.js"
$nodeExe = "node"

# Replace all: & qmd search $titleWords --limit 3 --json 2>&1
# With:        & $nodeExe $qmdScript search $titleWords --limit 3 --json 2>&1

# Replace all: & qmd vsearch $vsearchQuery --limit 3 --json 2>&1
# With:        & $nodeExe $qmdScript vsearch $vsearchQuery --limit 3 --json 2>&1
```

**Also set INDEX_PATH** — the hook needs to know where the qmd index lives:
```powershell
$env:INDEX_PATH = Join-Path $env:USERPROFILE ".cache\qmd\index.sqlite"
```

### Fix 2: Strip status words from vsearch queries (RECOMMENDED)

```powershell
# After extracting $firstSentence (line 258):
$cleanDesc = $firstSentence -replace '\b(DONE|IN PROGRESS|COMPLETE|TODO|BLOCKED|Phase \d+(\.\d+)?)\b', '' -replace '\s+', ' '
$vsearchQuery = "$threadTitle $cleanDesc".Trim()
```

### Fix 3: Preserve periods in keyword title extraction (RECOMMENDED)

```powershell
# Line 264 — change from:
$titleWords = $threadTitle -replace '[^\w\s]', '' -replace '\s+', ' '
# To:
$titleWords = $threadTitle -replace '[^\w\s.]', '' -replace '\s+', ' '
```

### Fix 4: Handle stderr pollution in JSON parsing (DEFENSIVE)

```powershell
# After $kwJson = ($kwRaw | Out-String).Trim()
# Find JSON array start:
$bracketIdx = $kwJson.IndexOf('[')
if ($bracketIdx -ge 0) {
    $kwJson = $kwJson.Substring($bracketIdx)
    # Proceed with ConvertFrom-Json
}
```

Note: The vec search code (lines 288-289) already has this bracket-finding pattern. The keyword search code (line 269) does not — it checks `$kwJson -match '^\['` which fails if stderr lines prepend the output.

## Additional Consideration: Task-Specific Context

The handoff asked whether the hook should also use the user's first message for task-specific context. This is a separate question from the broken qmd call, but:

- **Pro:** The first message often contains the actual task ("implement X", "fix Y"), which is more specific than goal threads
- **Con:** SessionStart hooks fire before the user's first message is available — by design, there's no stdin
- **Alternative:** A PreToolUse hook on the first agent action could inject task-specific context, but this adds latency to every first tool call

**Recommendation:** Fix the current goal-thread surfacing first (Fixes 1-4). Task-specific context is a separate enhancement that requires a different hook trigger point.
