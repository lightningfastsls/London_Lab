# Investigation 4.3: qmd Retrieval Precision Benchmark

> **Status:** COMPLETE
> **Date:** 2026-03-22
> **Context:** Priority 4.3 from arscontexta health restoration plan
> **Corpus:** 523 notes in mickey-lab collection, vector index current (0 needing embedding)

## Test Design

10 queries spanning domain, operational, cross-domain, and goal-thread categories.
Each run in lex (BM25) and vec (embedding) modes where possible.
Condensed variants test BM25 dilution hypothesis.
Self-retrieval test: 10 note descriptions used as lex queries.

**Constraint:** Vec/hyde modes only available through MCP server, which disconnected twice during testing. CLI vec search downloads a 1.28GB model and builds llama.cpp from source — no practical CLI fallback. Vec data is therefore incomplete.

## Findings

### Finding 1: qmd instability under parallel query load
Multiple vec queries run simultaneously cause "Object is disposed" errors. **Impact:** agents running multi-query workflows (like /ask or session-orient) may silently lose results.

### Finding 2: Hyphen-as-negation parsing bug
"VQ-VAE" in vec/hyde queries is parsed as "VQ" minus "VAE". **Workaround:** write "VQVAE" without hyphen. **Impact:** all hyphenated domain terms (VQ-VAE, self-supervised, cross-domain, pre-trained) may fail in semantic search.

### Finding 3: Lex search performs well for targeted domain terms (3-5 keywords)
Domain lex queries with specific terms found relevant results (83-100% P@1). BM25 works best when queries are tight keyword groups matching note vocabulary.

### Finding 4: Vec search precision is lower than lex for specific concepts
Vec returns semantic neighbors, not exact intent matches. CNN vec query returned a behavioral note instead of architecture note. Useful for discovery, not precise retrieval.

### Finding 5: Uniform 0.93 top scores across all queries
Every successful query returns ~0.93 regardless of actual relevance quality. **Impact:** threshold-based filtering (e.g., `minScore: 0.5`) is meaningless — it will either pass everything or nothing. Scores don't discriminate "perfect match" from "topically adjacent."

### Finding 6: CLI vec search has no practical fallback
The CLI `vsearch` command downloads a 1.28GB model and attempts to build llama.cpp from source (fails without GPU build tools). Vec/hyde modes are MCP-server-only, and that server is unstable (Finding 1). **Impact:** vec search has zero reliability guarantees.

### Finding 7: BM25 dilution is severe and confirmed (CRITICAL)
Full goal-thread prose (52 words) → 0 results. Same intent condensed to 4 keywords → 5 relevant hits. Status words ("DONE", "IN PROGRESS", "Phase 2/3") dilute BM25 scoring below the match threshold. **This is the root cause of session-orient returning "No strong matches."**

### Finding 8: Self-retrieval fails for 40% of notes
Notes with abstract/conceptual descriptions fail to self-retrieve via BM25. The description vocabulary doesn't overlap enough with the note body vocabulary. Descriptions optimized for human readability may not be optimized for BM25 retrieval.

### Finding 9: Operational/meta-knowledge queries fail
Queries about the vault's own operations (health checking, session mining) return 0 results because the vault stores domain knowledge, not operational self-knowledge. "arscontexta" and "schema compliance" have no notes — they live in CLAUDE.md and ops/ configs.

## Recommendations (ranked by effort/impact)

### 1. Fix session-orient query construction (HIGH impact, LOW effort)
Strip status words (DONE, IN PROGRESS, Phase N, percentages) from goal-thread text before querying. Extract domain terms only. This alone would fix the "No strong matches" issue for well-represented topics.
- **Estimated improvement:** Goal-thread queries go from 0% to ~50%+ P@1
- **File:** `.claude/hooks/session-orient.ps1` lines ~250-310

### 2. Report hyphen-as-negation bug upstream (MEDIUM impact, LOW effort)
File issue with qmd maintainer. Workaround: strip hyphens from query terms before vec/hyde calls.
- **Estimated improvement:** Eliminates vec query crashes for 15+ domain terms

### 3. Report parallel query crash upstream (MEDIUM impact, LOW effort)
File issue with qmd maintainer. Workaround: serialize all vec queries.
- **Estimated improvement:** Eliminates silent result loss in multi-query agents

### 4. Don't use score thresholds for filtering (LOW effort)
The uniform 0.93 scoring makes `minScore` useless. Either return all results and let the agent judge relevance, or use rank-based cutoffs (top-K) instead.

### 5. Improve descriptions for BM25 recall (HIGH impact, MEDIUM effort)
For the 40% of notes that fail self-retrieval, add 2-3 distinctive keyword phrases to descriptions. Focus on ensuring description vocabulary overlaps with note body vocabulary.
- **Audit target:** Notes with abstract/conceptual descriptions
- **Pattern:** Successful descriptions include specific tool names, numbers, or technical terms

### 6. Accept operational query gap (NO effort)
The vault correctly doesn't store notes about its own procedures. Operational queries should route to ops/ files and CLAUDE.md, not to qmd. This is a routing issue, not a retrieval issue.

### 7. Defer OpenViking investigation (conditional)
Query construction fixes (recommendation 1) are likely sufficient. If self-retrieval improvement (recommendation 5) raises the rate above 80%, there's no retrieval ceiling that requires a different engine.
