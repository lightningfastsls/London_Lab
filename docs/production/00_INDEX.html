How to read these. Every doc is layered: a §1 Operate section (exact commands, every parameter explained, where inputs/outputs live, how to read results, troubleshooting), followed by a §2 Internals section (architecture, data flow, function signatures, invariants). If you only want to run something, read §1. Paths and CLI flags were each re-opened and verified in the source — a wrong flag here is the failure mode we worked hardest to prevent.
The single most important distinction. The PyQt app's Detect button runs the CNN + hysteresis only (raw probabilities, no FP-filter / temperature / soft-notch). The full production pipeline (temperature + FP-filter + hysteresis + soft-notch + triage) is batch-only, via run_batch_detection.py. They are not interchangeable — applying the FP-filter in the app's context has previously suppressed real detections. See the CNN and Batch docs below.

The one command you'll run most

.venv/bin/python scripts/run_batch_detection.py \ --wav-dir <WAV_FOLDER>/ \ --model models/hard_neg_retrain/best_model.pt \ --output-dir results/batch_<NAME>/ \ --temperature models/hard_neg_retrain/temperature.json \ --fp-filter models/hard_neg_retrain/fp_filter.pkl \ --hysteresis-config models/hard_neg_retrain/hysteresis_optimization_v2.json \ --workers 4

All five artifact flags are required — omitting --fp-filter or --hysteresis-config produces an incomplete pipeline with unreliable triage. Full explanation in batch_detection.md.

Open questions for the author (your call)

  • Labeling tool scope. The file originally named ("PyQt6 labeling app", labeling/labeling_app.py) is a retired Streamlit app whose run() now exits immediately. The live labeling tool is the PyQt6 app under app/, which the doc covers. Confirm this is the intended scope.
  • Three-way syllable taxonomy gap. The live PyQt6 app records per-detection USV intervals + a whole-file noise flag — not the three-way USV / Not-USV / Uncertain syllable labeling that existed only in the retired Streamlit app. If the lab still needs three-way syllable labeling, there is currently no supported tool for it.
  • Shape-clustering durability. The registered-ridge meta NPZ that the shape builders depend on is not git-tracked — it lives only in ephemeral job tmp dirs and is regenerable only on the rig. Worth promoting to a durable tracked location before the next person needs it.
  • Two source-level inconsistencies to reconcile (flagged, not silently "fixed"): eval_report.md reports both 0.083 and 0.157 for the max confusion fraction; and denoise.py's docstring says "1170" where the computed kernel is 1172. The docs state the correct computed values; the source comments should be reconciled by the code owner.
