# Corpus Constants (`usv_spectrogram.corpus`)

**Status:** Live (landed 2026-04-17)
**Single source of truth for:** sample rate, USV frequency band, STFT parameters
**Key constraint:** values are locked to the production CNN training grid

---

## Why this module exists

Before this refactor, four config modules declared the same physical
constants with different values:

| Module | Sample rate | freq_min | freq_max |
|---|---|---|---|
| `SpectrogramConfig` | 250_000 | 30_000 | 125_000 |
| `DetectionConfig` | 300_000 | 25_000 | 110_000 |
| `ExtractionConfig` | 300_000 | 20_000 | 120_000 |
| `AnalysisConfig` | n/a | 20_000 | 120_000 |

The `SpectrogramConfig` value of 250 kHz contradicted `CLAUDE.md` ADR-001
(which specifies 300 kHz), giving us a latent bug: any `SpectrogramConfig()`
loaded against a real 300 kHz WAV would raise a sample-rate mismatch. The
refactor collapses all four onto one set of canonical values.

## Three-layer architecture

```
┌─────────────────────────────────────────────────────────┐
│ Layer 1 — CORPUS CONSTANTS (physical facts)             │
│   src/usv_spectrogram/corpus.py                         │
│   SAMPLE_RATE_HZ, USV_FREQ_{MIN,MAX}_HZ, STFT_N_FFT,    │
│   STFT_HOP + derived helpers                            │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│ Layer 2 — EMPIRICAL DATA (per dataset)                  │
│   data/corpus_facts/{5970,3452,9252}.json               │
│   Generated by scripts/audit_corpus.py from classified  │
│   CSVs + Phase A1/A2 outputs.                           │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│ Layer 3 — ANALYSIS PARAMETERS (per-module, unchanged)   │
│   SpectrogramConfig / DetectionConfig / AnalysisConfig  │
│   Same shape as before — import Layer 1 constants       │
│   instead of redeclaring.                               │
└─────────────────────────────────────────────────────────┘
```

## Canonical values (2026-04-17)

```python
SAMPLE_RATE_HZ   = 300_000    # LMT rig; Nyquist = 150 kHz
USV_FREQ_MIN_HZ  = 20_000     # CNN training band (lower edge)
USV_FREQ_MAX_HZ  = 120_000    # CNN training band (upper edge)
STFT_N_FFT       = 512        # ~586 Hz freq resolution at 300 kHz
STFT_HOP         = 128        # 75 % overlap (~0.43 ms at 300 kHz)
```

Derived helpers (functions, not constants — the formula stays visible):

```python
nyquist_hz()             -> 150_000
stft_freq_resolution_hz() -> 585.9375
stft_time_resolution_ms() ->   1.7066
stft_hop_ms()             ->   0.4266
```

## CNN freeze (critical)

The production CNN (`models/hard_neg_retrain/best_model.pt`) was trained
on 256-pixel-tall spectrograms covering exactly **20–120 kHz**. Changing
`USV_FREQ_MIN_HZ` or `USV_FREQ_MAX_HZ` here without retraining produces
**silently-wrong inference** — same pixel grid, different Hz-per-pixel,
features shifted to the wrong rows.

`ExtractionConfig` holds those CNN-training literals *directly* (20_000
and 120_000, hardcoded, NOT imported from `corpus.py`) with a module-level
drift assertion at the bottom of `src/usv_spectrogram/detection/extraction_config.py`:

```python
assert _FIELDS["freq_max_hz"].default == _CORPUS_USV_FREQ_MAX_HZ, (
    "ExtractionConfig.freq_max_hz drifted from corpus.USV_FREQ_MAX_HZ. "
    "If corpus changed, retrain the CNN before updating this literal."
)
```

If you need to change the corpus band, the correct sequence is:
1. Retrain the CNN on the new band
2. Update `ExtractionConfig` literals to match
3. Update `corpus.py` constants
4. The drift assertion will pass on the next import

Never reverse this order.

## Usage

```python
from usv_spectrogram.corpus import (
    SAMPLE_RATE_HZ,
    USV_FREQ_MIN_HZ,
    USV_FREQ_MAX_HZ,
    STFT_N_FFT,
    STFT_HOP,
)

# In a new config class:
@dataclass(frozen=True)
class MyNewConfig:
    sample_rate: int = SAMPLE_RATE_HZ
    freq_min_hz: int = USV_FREQ_MIN_HZ
    freq_max_hz: int = USV_FREQ_MAX_HZ

# In an analysis script — cite, don't redeclare:
from usv_spectrogram import corpus
print(f"Nyquist: {corpus.nyquist_hz()} Hz")
```

## Empirical data registry (`data/corpus_facts/`)

Layer 2 stores *measured* per-dataset stats that are expensive to recompute:
median ICI, bout counts, Phase A2 transition pair counts, labeling
distributions. Generated by:

```bash
python scripts/audit_corpus.py --dataset 5970 --output data/corpus_facts/5970.json
python scripts/audit_corpus.py --all   # 5970 + warns for 3452/9252 until those ship
```

Schema (abbreviated — see `data/corpus_facts/5970.json` for the full form):

- `sources` — paths every stat was derived from (traceability)
- `counts` — `n_calls_raw`, `n_calls_after_dropna_file`, `n_files`, `n_sessions`
- `timing` — `median_ici_gap_ms`, `median_ioi_ms`, `median_call_duration_ms`, quantiles
- `bout_detection_a2` — threshold, derivation, bout counts
- `labeling_distributions` — Scattoni-7 and HDBSCAN counts
- `references` — literature values (Hertz 2020 SIS, median within-bout gap, etc.)

## Adding a new dataset

1. Produce the classified CSV, ICI `.npy` files, and Phase A2 summary for the new dataset
2. Edit `DATASET_REGISTRY` in `scripts/audit_corpus.py` with the paths
3. Run `python scripts/audit_corpus.py --dataset <NAME> --output data/corpus_facts/<NAME>.json`
4. Commit the JSON as a versioned artifact
