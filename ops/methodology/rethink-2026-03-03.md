## New Pattern Analysis

### Pattern D: "Proposal implementation gap — skill spec changes compete with domain work"

**Evidence:** Proposals 3 and 4 from the prior rethink were marked "ready to implement" but not implemented. The intervening session focused on bulk knowledge ingestion (rounds 1-4, ~200 notes) and topic map splits. Skill spec edits require a different work mode (editing SKILL.md files, testing the skill) that doesn't fit naturally into a knowledge-processing session.

**Root cause:** The reminder system flags WHEN to do something but doesn't create the right context for HOW. A reminder saying "Apply /reduce description self-check" appears at session orient alongside "inbox has 3 items" and "topic maps need splitting" -- the domain work wins because it has clearer deliverables.

**Implication:** Skill spec improvements need to be either (a) done immediately in the same session as the rethink that proposes them, or (b) explicitly scheduled as the PRIMARY task of a dedicated session (not a secondary reminder alongside domain work).

### Pattern E: "Topic map sprawl persists despite splits — the 40-note threshold is now routinely exceeded"

**Evidence:** After the 2026-03-03 splits (classification -> 3 maps, agent-governance -> 2 maps, detection -> 2 maps), the vault has 23 topic maps. Current link counts exceeding 40:

| Map | Wiki-links | Status |
|-----|-----------|--------|
| representation-learning | 53 | Over (1.3x) |
| agent-governance | 45 | Over (1.1x) -- even after split |
| classification-methodology | 44 | Over (1.1x) -- new child map, already at threshold |
| agent-cognition | 44 | Over (1.1x) |
| transformer-architecture | 42 | Over (1.05x) |
| context-management | 41 | Over (1.02x) |

**Root cause:** The 40-note threshold was designed for a vault of ~100-150 notes. With 507 notes across 23 maps, the average map has ~22 notes, but the distribution is heavy-tailed. Bulk ingestion creates batches of related notes that cluster onto the same maps. Splitting produces children that are already near-threshold because the natural topic boundaries cluster at 30-45 notes.

**Implication:** Two options: (1) raise the split threshold to 50 (accept denser maps now that the hierarchy is deeper), or (2) accept continuous splitting as a maintenance cost. The arscontexta-expert's guidance ("MOC health range 10-40") suggests 40 is methodologically sound. But the vault's growth trajectory means maps will keep exceeding 40 after every ingestion round. Option 1 is pragmatic: increase the warning threshold to 50 and the critical threshold to 60, reflecting the vault's maturity.

## Proposals

### Proposal 6: Enforce arscontexta-expert consultation before structural KG changes

**Problem:** Observation #10 -- agent started topic map split before consulting arscontexta-expert, requiring mid-process correction.

**Change:** Add an explicit step to the CLAUDE.md Knowledge Graph > Topic Maps section:

```
**Before any topic map split, merge, or creation:** consult arscontexta-expert for
methodology grounding. The expert validates split boundaries, prevents premature
subordinate-level splits (< 15 notes), and ensures context phrase quality.
```

Also add to the agent table: a column indicating "Required BEFORE" vs "Required AFTER" for each agent, so the sequencing is explicit.

**Validation:** Next structural KG change should show arscontexta-expert consultation in the first step, not mid-process.

**Status:** Ready to implement (lightweight CLAUDE.md edit).

### Proposal 7: Raise topic map split thresholds to reflect vault maturity

**Problem:** Pattern E -- 6 of 23 maps exceed the 40-note threshold, including maps that were just split. The current threshold produces false urgency.

**Change:** Update CLAUDE.md Knowledge Graph > Topic Maps section:

```
Split when a topic map exceeds ~50 notes (warning at 40, critical at 60).
```

Update ops/config.yaml or the /health skill to use the new thresholds.

**Validation:** After applying, only representation-learning (53 notes) should trigger a warning. No maps should be critical. The next /health run should reflect the updated thresholds.

**Status:** Ready to implement. Should be validated with arscontexta-expert (Proposal 6 applies here).

### Proposal 8: Same-session implementation window for "ready" rethink proposals

**Problem:** Pattern D -- proposals marked "ready to implement" get deferred because they compete with domain work in subsequent sessions.

**Change:** After the rethink report is written and approved, immediately implement all "ready to implement" proposals in the SAME session. The rethink session should have two phases:

1. **Analysis phase:** Triage, pattern detection, proposal generation, report writing
2. **Implementation phase:** Apply all approved "ready" proposals (CLAUDE.md edits, skill spec changes, archiving)

This eliminates the handoff gap. Add to the /rethink skill spec:

```
After report approval, implement all "Ready to implement" proposals before ending
the session. Do not defer to reminders — reminders compete with domain work and lose.
```

**Validation:** The next rethink should show 0 "ready but not implemented" proposals from the prior session.

**Status:** Meta-proposal (changes the /rethink workflow itself). Apply starting now.
